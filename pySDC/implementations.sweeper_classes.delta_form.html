implementations.sweeper_classes.delta_form module¶

Deferred-correction (“delta-form”) SDC sweepers.

A standard SDC sweep

\[u^{k+1}_m = u_0 + \tau_m + \Delta t (Q f^k)_m + \Delta t \sum_j Q^\Delta_{mj}\,(f^{k+1}_j - f^k_j)\]

is algebraically identical to, with \(\delta_m = u^{k+1}_m - u^k_m\) and the collocation residual \(\varepsilon_m = u_0 + \tau_m + \Delta t (Q f^k)_m - u^k_m\),

\[\delta_m = \varepsilon_m + \Delta t \sum_j Q^\Delta_{mj}\,\Delta f_j, \qquad \Delta f_j = f(u^k_j + \delta_j) - f(u^k_j).\]

Written this way, every sweep is iterative refinement: a high-precision residual, a correction solve, and a high-precision update u <- u + delta. No Jacobian appears, so an IMEX splitting survives unchanged.

The point of the reformulation is that the quantity handed to the node-local solver is a correction. Its magnitude tends to zero as the sweeps converge, so a reduced-precision solve introduces an error proportional to \(|\delta|\) rather than to \(|u|\) and therefore does not cap the attainable accuracy.

Three node-local strategies are supported, selected automatically:

solve_system_delta

Used when the problem provides it. Solves \(\delta - \alpha[f(w+\delta) - f(w)] = r\) for the correction directly. This is the only option for a nonlinear implicit operator, and the only one that hands a reduced-precision solver a small unknown.

linear_implicit=True

For a linear or affine implicit operator, \(f(w+\delta) - f(w) = A\delta\), so the stock solve_system already solves the correction equation once the affine part \(\alpha f(0, t)\) is removed from the right-hand side. No problem class needs changing.

fallback

Otherwise the substitution \(y = u^k_m + \delta_m\) reduces the correction equation to the ordinary implicit solve. Always correct and identical to generic_implicit, but the solver sees an \(\mathcal{O}(1)\) unknown, so there is no precision benefit.

correction_precision additionally stores the small quantities (\(\varepsilon\), \(\delta\), \(\Delta f\)) in a reduced-precision datatype built from the problem’s own init tuple, scaled by the residual’s magnitude so the format’s mantissa is used however small the correction gets.

The increment \(\Delta f\) is formed by subtracting two stored right-hand sides unless the problem provides eval_f_increment(base, delta, t), which expands it analytically. That subtraction is a cancellation carrying the operator norm, so it binds as soon as a level runs below backend precision.

The same sweeper serves any number of levels, and which it is doing is decided by the transfer, not by the choice of sweeper. On the finest level it computes its own residual, which is where the accuracy of the whole iteration is set. Given a transfer that hands one down – by setting eps_in on the level’s sweeper – it uses that instead and advances it in place, so nothing is ever rebuilt out of \(\mathcal{O}(1)\) coarse state. BaseTransfer hands nothing down, so on a stock hierarchy this sweeper reproduces MLSDC and PFASST exactly.

advance_residual(eps, deltas, dfs)[source]¶

Advance a residual by an update: \(\varepsilon \leftarrow \varepsilon - \delta + \Delta t (Q \Delta f)\).

Every term is small, so this never cancels. It is exact for any update to the nodal values, which is why it serves both a sweep and a prolongation.

  • deltas (list) – The update applied to the nodal values, one entry per node.

  • dfs (list) – The resulting right-hand side increments, one entry per node.

compute_residual(stage='')[source]¶

Report the residual this level is already tracking, instead of rebuilding one.

A level with an inherited residual carries it forward through every sweep and prolongation, so recomputing it from \(\mathcal{O}(1)\) state would be both redundant and less accurate. It is also what makes the \(\tau\) term unnecessary: the only other reader is compute_end_point(), and only when the end point comes from the quadrature update.

Parameters:

stage (str) – The stage of the step this level belongs to.

sync_initial_value()[source]¶

Follow a change of \(u_0\) made after the residual was handed down.

PFASST receives the initial value from the predecessor after the restriction, directly into u[0]. The residual depends on it additively, so following it is one addition: \(\varepsilon_m \leftarrow \varepsilon_m + (u_0 - u_0^{\mathrm{ref}})\). Exactly zero when nothing arrived, which is every serial run.

This is the one place the hierarchy still differences two \(\mathcal{O}(1)\) values, and it is the reason a reduced-precision coarse level buys less under PFASST than under MLSDC: the difference is small – it is the coarse-versus-fine discrepancy at the step interface, and it converges to zero – but it is formed by cancelling two values of size \(|u|\). Putting the step-to-step exchange itself in delta form is what would remove it.

Return type:

None

update_nodes()[source]¶

Sweep, and keep the level’s bookkeeping straight if it is part of a hierarchy.

The sweep itself is _sweep_nodes(), which each concrete sweeper supplies. Around it: follow any change of \(u_0\) that arrived after the residual was handed down, advance that residual by the update just applied, and bank the corrections for a transfer to prolong.

A level that computes its own residual has no bookkeeping to do, so on a single-level run every line below the sweep is a no-op. That is why there is one sweeper rather than two.

Return type:

None
