13# # Part G: pySDC from Firedrake forms 

14# 

15# In [Part D](D_pySDC_with_Firedrake), the heat equation comes with a ready-made problem class. Here we write our own 

16# problem without writing a class at all: we write down the weak form of the equation, as we would for Firedrake 

17# anyway, and the generic problem class 

18# [`FormFiredrake`](https://github.com/Parallel-in-Time/pySDC/blob/master/pySDC/implementations/problem_classes/FormFiredrake.py) 

19# builds everything pySDC needs from it. Part D's heat equation is itself built this way. 

20# 

21# ## The equation and its weak form 

22# 

23# We solve a reaction-diffusion equation of Allen-Cahn type on the unit square, 

24# 

25# $$ 

26# u_t = \nu \Delta u + u - u^3 + g, 

27# $$ 

28# 

29# with Dirichlet boundary values. The forcing $g$ and the boundary values come from a solution $u_e(x, y, t)$ we pick, 

30# so that we can measure the error: this is the *method of manufactured solutions*. 

31# 

32# Finite elements turn the equation into a system of ordinary differential equations, $M u' = R(u)$, for the 

33# coefficients $u$ of the finite element function. The *mass matrix* $M$ and the right-hand side $R$ come from 

34# multiplying the equation by a test function $v$ and integrating over the domain, integrating the Laplacian by parts: 

35# 

36# $$ 

37# \underbrace{\int u_t\, v\, dx}_{m(u_t, v)} 

38# = \underbrace{-\nu \int \nabla u \cdot \nabla v\, dx}_{\text{diffusion}} 

39# + \underbrace{\int (u - u^3)\, v\, dx}_{\text{reaction}} + \int g\, v\, dx. 

40# $$ 

41# 

42# These *forms* are all `FormFiredrake` needs. We give each as a Python function of the solution `u` and the test 

43# function `v`, written in [UFL](https://www.firedrakeproject.org/variational-problems.html), the form language 

44# Firedrake uses. Time enters through a Firedrake `Constant` `t`: pySDC sets it to the right time before every 

45# evaluation and solve, so forms, boundary values and the exact solution may all depend on it. 

46# 

47# The forcing is the one part we do not write by hand. `manufactured_forcing` inserts $u_e$ into the forms, and UFL 

48# differentiates it in time, so $g$ is exact for whatever $u_e$ we choose. Ours is quadratic in space, so the finite 

49# elements represent it exactly and all of the error we see comes from the time stepping. 

50 

51# %% 

52from pathlib import Path 

53 

54import firedrake as fd 

55 

56from pySDC.helpers.ufl_forms import manufactured_forcing, total_rhs 

57 

58NU = 0.1 

59 

60 

61def get_forms(imex, mesh): 

62 """ 

63 The problem as forms, for `FormFiredrake` or `FormFiredrakeIMEX`. 

64 

65 Args: 

66 imex (bool): Whether to put the reaction into the explicit part 

67 mesh (firedrake.MeshGeometry): The mesh 

68 

69 Returns: 

70 dict: The problem parameters 

71 """ 

72 V = fd.FunctionSpace(mesh, 'CG', 2) 

73 x, y = fd.SpatialCoordinate(mesh) 

74 t = fd.Constant(0.0) 

75 

76 u_exact = fd.cos(t) * (1 + x**2 + 2 * y**2) / 4 

77 

78 def mass(u, v): 

79 return u * v * fd.dx 

80 

81 def diffusion(u, v): 

82 return -NU * fd.inner(fd.grad(u), fd.grad(v)) * fd.dx 

83 

84 def reaction(u, v): 

85 return (u - u**3) * v * fd.dx 

86 

87 forcing = manufactured_forcing(mass, total_rhs(diffusion, reaction), u_exact, t, fd.TestFunction(V)) 

88 

89 params = { 

90 'V': V, 

91 'mass': mass, 

92 't': t, 

93 'u_exact': u_exact, 

94 # a tuple: pySDC would read a list as one entry per level 

95 'bcs': (fd.DirichletBC(V, u_exact, 'on_boundary'),), 

96 } 

97 if imex: 

98 params['rhs'] = lambda u, v: diffusion(u, v) + forcing 

99 params['rhs_exp'] = reaction 

100 else: 

101 params['rhs'] = lambda u, v: diffusion(u, v) + reaction(u, v) + forcing 

102 return params 

103

106# ## Implicit or IMEX 

107# 

108# `FormFiredrake` treats the whole right-hand side implicitly, so every SDC node needs a nonlinear solve. Firedrake 

109# does it with Newton's method, and the Jacobian comes from differentiating the forms symbolically. `FormFiredrakeIMEX` 

110# takes a second, explicit right-hand side: here the reaction, so the implicit systems become linear. The problem class 

111# notices that from the forms: it then solves each system with one linear solve instead of Newton's method, and since 

112# the operator does not depend on time either, it factorizes it once per prefactor and keeps the factorization. Either 

113# way, the problem class never inverts the mass matrix. It hands pySDC $M u$ and $R(u)$ instead, which is what the 

114# *mass-matrix sweepers* `generic_implicit_mass` and `imex_1st_order_mass` work with. 

115# 

116# The boundary values enter only in the solves. As a result, the rows of the SDC residual that belong to boundary 

117# nodes carry no equation, and the problem class leaves them out of the residual it reports. 

118# 

119# The residual is a load vector like $R(u)$, and its size is measured with the norm that belongs to load vectors: the 

120# $L^2$ norm of the function it represents, $\sqrt{r^T M^{-1} r}$. It does not shrink as the mesh is refined, so a 

121# residual tolerance means the same on every mesh. Here, `restol = 1e-8` is where the iterations reach the accuracy 

122# of the collocation problem; a smaller one only adds iterations. 

123

126def setup(imex, levels=1): 

127 """ 

128 Helper routine to set up parameters 

129 

130 Args: 

131 imex (bool): Whether to run IMEX SDC instead of fully implicit SDC 

132 levels (int): Number of levels, 1 for SDC or 2 for MLSDC 

133 

134 Returns: 

135 description and controller_params parameter dictionaries 

136 """ 

137 from pySDC.implementations.problem_classes.FormFiredrake import FormFiredrake, FormFiredrakeIMEX 

138 from pySDC.implementations.sweeper_classes.generic_implicit_mass import generic_implicit_mass 

139 from pySDC.implementations.sweeper_classes.imex_1st_order_mass import imex_1st_order_mass 

140 from pySDC.implementations.transfer_classes.BaseTransfer_mass import base_transfer_mass 

141 from pySDC.implementations.transfer_classes.TransferFiredrakeMesh import MeshToMeshFiredrakeHierarchy 

142 from pySDC.implementations.hooks.log_errors import LogGlobalErrorPostRun 

143 from pySDC.implementations.hooks.log_work import LogWork 

144 

145 # an 8x8 mesh made by refining a 4x4 one, so that the two can be levels 

146 meshes = fd.MeshHierarchy(fd.UnitSquareMesh(4, 4), 1)[::-1][:levels] 

147 forms = [get_forms(imex, mesh) for mesh in meshes] 

148 

149 description = { 

150 'problem_class': FormFiredrakeIMEX if imex else FormFiredrake, 

151 # one entry per level, finest first: each level has its own mesh, and so its own spaces and boundary values 

152 'problem_params': {key: [level[key] for level in forms] for key in forms[0]}, 

153 'sweeper_class': imex_1st_order_mass if imex else generic_implicit_mass, 

154 'sweeper_params': {'quad_type': 'RADAU-RIGHT', 'num_nodes': 3, 'QI': 'LU'}, 

155 'level_params': {'restol': 1e-8, 'dt': 0.1}, 

156 'step_params': {'maxiter': 20}, 

157 'base_transfer_class': base_transfer_mass, 

158 'space_transfer_class': MeshToMeshFiredrakeHierarchy, 

159 } 

160 controller_params = {'logger_level': 30, 'hook_class': [LogGlobalErrorPostRun, LogWork]} 

161 return description, controller_params 

162

164# %% [markdown] 

165# ## Several levels 

166# 

167# For multilevel SDC (MLSDC) and PFASST, each level needs its own problem on its own mesh. We take the meshes from a 

168# Firedrake `MeshHierarchy`, so that they are nested, and give the problem parameters as lists, one entry per level, 

169# finest first. Two transfer classes move data between the levels: 

170# 

171# - `MeshToMeshFiredrakeHierarchy` restricts solutions by $L^2$ projection, restricts load vectors such as $M u_0$ with 

172# the transpose of the prolongation, and prolongs corrections; 

173# - `base_transfer_mass` puts these together into the FAS correction for the mass formulation. 

174# 

175# On the coarse level, the solves impose the boundary values of the restricted fine solution rather than the boundary 

176# data, so that the coarse correction vanishes on the boundary. Without this, MLSDC would not converge to the solution 

177# of SDC. 

178# 

179# ## Running it 

180# 

181# The run prints the error at the end, the SDC iterations and the work of the problem class: how many solvers it set 

182# up (one per distinct diagonal entry of the preconditioner), how many systems it solved, and how many linear solves 

183# those took in total, including Newton's. 

184 

185 

186# %% 

187def run(imex, levels=1): 

188 """ 

189 Run the example with fully implicit or IMEX SDC, or MLSDC 

190 

191 Args: 

192 imex (bool): Whether to run IMEX SDC instead of fully implicit SDC 

193 levels (int): Number of levels, 1 for SDC or 2 for MLSDC 

194 

195 Returns: 

196 dict: Error, iterations and work of the run 

197 """ 

198 import numpy as np 

199 from pySDC.implementations.controller_classes.controller_nonMPI import controller_nonMPI 

200 from pySDC.helpers.stats_helper import get_sorted 

201 

202 description, controller_params = setup(imex, levels) 

203 controller = controller_nonMPI(num_procs=1, controller_params=controller_params, description=description) 

204 

205 P = controller.MS[0].levels[0].prob 

206 uend, stats = controller.run(u0=P.u_exact(0.0), t0=0.0, Tend=1.0) 

207 

208 result = {'error': get_sorted(stats, type='e_global_post_run')[0][1]} 

209 result['niter'] = int(np.sum([me[1] for me in get_sorted(stats, type='niter')])) 

210 for key in ['work_solver_setup', 'work_solver', 'work_ksp']: 

211 # the work on the finest level 

212 result[key] = int(np.sum([me[1] for me in get_sorted(stats, type=key, level=0)])) 

213 

214 variant = ('IMEX' if imex else 'implicit') + (' SDC' if levels == 1 else ' MLSDC') 

215 summary = ( 

216 f'{variant:14s}: error {result["error"]:.2e}, {result["niter"]} iterations, ' 

217 f'{result["work_solver_setup"]} solver setups, {result["work_solver"]} solves, ' 

218 f'{result["work_ksp"]} linear solves' 

219 ) 

220 print(summary) 

221 Path('data').mkdir(parents=True, exist_ok=True) 

222 with open('data/step_7_G_out.txt', 'a') as file: 

223 file.write(summary + '\n') 

224 return result 

225 

226 

227def main(): 

228 """Run the variants and check that we got the same as last time.""" 

229 implicit = run(imex=False) 

230 imex = run(imex=True) 

231 multilevel = run(imex=False, levels=2) 

232 

233 for result in [implicit, imex, multilevel]: 

234 assert result['error'] < 1e-8, result 

235 assert result['work_solver_setup'] == 3, result 

236 assert result['work_solver'] == 3 * result['niter'], result 

237 

238 # the reaction is mild enough that moving it to the explicit side costs no extra iterations here 

239 assert implicit['niter'] == 61 and imex['niter'] == 59, (implicit, imex) 

240 # the IMEX systems are linear: one linear solve each, while Newton needs a few 

241 assert imex['work_ksp'] == imex['work_solver'], imex 

242 assert implicit['work_ksp'] > implicit['work_solver'], implicit 

243 # MLSDC reaches the same accuracy, in about as many iterations as SDC, see below 

244 assert multilevel['niter'] == 66, multilevel 

245 return implicit, imex, multilevel 

246

249if __name__ == "__main__": 

250 main()

252# %% [markdown] 

253# All variants reach the same accuracy. IMEX SDC solves one linear system per node and iteration, where fully implicit 

254# SDC runs Newton's method. Which one is cheaper overall depends on how stiff the explicit part is: a stiffer reaction 

255# would cost IMEX SDC iterations, or a smaller step size. 

256# 

257# MLSDC does not pay off for this problem: SDC already converges in about six iterations per step, and MLSDC needs as 

258# many, plus the sweeps on the coarse level. A coarse level helps when SDC needs many iterations, for instance with 

259# stronger diffusion or larger steps, and it is what lets PFASST compute several steps in parallel.
